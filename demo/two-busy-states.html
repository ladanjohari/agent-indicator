Why two busy states

The same task, twice. On the left it goes normally. On the right, the command it started never exits: a dev server, a prompt nobody can see, a wedged build.

Neither one ever turns amber, because amber means it needs you, and neither of them does. So the only thing that tells you the right hand session is broken is that Running a command has been on screen for forty minutes.

write-docs

Healthy.

  • 0s Idle
  • 2s Writing
  • 6s Running a command
  • 11s Writing
  • 14s Done

dev-server

The command never exits.

  • 0s Idle
  • 2s Writing
  • 6s Running a command
  • 12m Running a command
  • 41m Running a command

Now merge Writing and Running a command into one busy state. Both columns become the same column, and there is nothing left on screen that could ever tell you the right hand session died forty minutes ago.
